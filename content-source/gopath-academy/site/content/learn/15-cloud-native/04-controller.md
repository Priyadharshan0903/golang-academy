## What you will learn

- What a custom resource and an operator are
- Defining an API with Go types and **kubebuilder markers**, and generating the CRD, deep-copy code and RBAC with **controller-gen**
- Writing a **Reconcile** function that is safe to run any number of times

- Reporting progress through **status** and **conditions**
- Testing reconcilers with controller-runtime's fake client, and running the operator on a cluster

## The idea

Kubernetes is extensible: a **CustomResourceDefinition** (CRD) adds a new kind of object to the API, and a **controller** makes the world match those objects. Together they are an **operator**: you declare what you want in YAML, and a program keeps it true.

This lesson builds one for the course's shortener. A `ShortLink` resource declares a short link:

```yaml
apiVersion: shortener.example.com/v1alpha1
kind: ShortLink
metadata:
  name: k8s-docs
spec:
  url: https://kubernetes.io/docs
  code: k8s
```

and the operator creates it through the shortener's HTTP API, keeps it pointing at `spec.url`, reports the short URL in the status, and deletes it when the resource is deleted. On the test cluster:

```text
$ kubectl -n shortener apply -f config/samples/shortlink.yaml
$ kubectl -n shortener get shortlinks
NAME       CODE      SHORT URL                               READY   AGE
go-docs    go-docs   http://shortener.localtest.me/go-docs   True    28s
k8s-docs   k8s       http://shortener.localtest.me/k8s       True    28s

$ curl -si -H "Host: shortener.localtest.me" http://127.0.0.1/k8s | grep -E '^(HTTP|Location)'
HTTP/1.1 302 Found
Location: https://kubernetes.io/docs
```

The project is in [`projects/shortlink-operator`](https://github.com/Priyadharshan0903/gopath-academy/tree/main/projects/shortlink-operator), its own module, using **controller-runtime**, the library under Kubebuilder and the Operator SDK.

## The API, as Go types

{{< example file="projects/shortlink-operator/api/v1alpha1/shortlink_types.go" region="types" >}}

The shape is the same for every Kubernetes object: `TypeMeta` (kind and API version), `ObjectMeta` (name, namespace, labels, finalizers, generation), a **spec** written by users, and a **status** written by the controller. Status uses the standard `metav1.Condition` type, so tools such as `kubectl wait --for=condition=Ready` work with it.

The `+kubebuilder:...` comments are **markers**. They are read by **controller-gen**, run through the `//go:generate go tool controller-gen ...` line in the same file, with the version pinned by the module's `tool` directive (lesson 14.3). It generates:

- `zz_generated.deepcopy.go`: `DeepCopy` methods, which every Kubernetes object type needs (caches hand out shared objects, and code must copy before modifying);
- `config/crd/shortener.example.com_shortlinks.yaml`: the CRD, with an OpenAPI schema built from the Go types and the validation markers;
- `config/rbac/role.yaml`: a ClusterRole built from the `+kubebuilder:rbac` markers in the controller.

The validation markers run **in the API server**, before the operator ever sees a bad object:

```text
$ kubectl apply -f bad.yaml
The ShortLink "bad" is invalid:
* spec.code: Invalid value: "a b": spec.code in body should match '^[A-Za-z0-9_-]{3,32}$'
* spec.url: Invalid value: "ftp://files.example.com": spec.url in body should match '^https?://'
```

and the field comments become documentation: `kubectl explain shortlink.spec` prints them.

## The reconciler

{{< example file="projects/shortlink-operator/internal/controller/shortlink_controller.go" region="reconcile" >}}

**Reconcile does not receive an event.** It receives a name, and must look at the current state of the world and move it toward the desired state. It is called when the object changes, when it is created, after a restart, and on a periodic resync, perhaps several times for one change. So it must be **idempotent**: running it again when everything is already correct does nothing harmful. The test checks exactly that:

```text
first reconcile:  [get go-docs create go-docs]
second reconcile: [get go-docs]
```

How this one stays idempotent and safe:

- **A deterministic identifier.** Without `spec.code`, the code is the resource's name. If the code were random and the operator crashed between creating the link and saving the status, the next attempt would create a second link and orphan the first. Derive external identifiers from the object whenever you can.
- **Check before acting.** It reads the link first, and only creates, recreates or deletes when the state differs from the spec.
- **Ownership.** It only recreates a link that it created itself (`status.code == code`); a link someone else made with the same code produces a `CodeTaken` condition instead of being overwritten.
- **Errors mean "try again".** Returning an error makes controller-runtime requeue the request with exponential backoff, so a shortener outage is retried automatically. A condition that retrying soon cannot fix (`CodeTaken`) returns `RequeueAfter` instead.

## Cleaning up with a finalizer

Deleting a `ShortLink` must also delete the link in the shortener, an external system Kubernetes knows nothing about. A **finalizer** is a string in `metadata.finalizers` that tells the API server: do not remove this object until this finalizer is gone. Deleting the object then only sets `deletionTimestamp`; the reconciler sees that, cleans up, and removes its finalizer, and only then does the object disappear.

This was visible on the cluster. The first version of the shortener deployed there had no DELETE endpoint yet, so `kubectl delete shortlink k8s-docs` **waited**, and the operator logged `DELETE /api/links/k8s: HTTP 405` and retried with backoff. Once the shortener was upgraded, the next retry succeeded, the finalizer was removed, the delete completed, and `/k8s` returned 404. That is the guarantee working: the Kubernetes object cannot vanish while the external resource still exists.

The **manager** owns the shared informer cache (lesson 15.3), the clients, the controllers, metrics on `:8080`, health probes on `:8081`, leader election, and signal handling. `For(&ShortLink{})` sets up an informer and a work queue for ShortLinks; controller-runtime then calls `Reconcile` for each key in the queue, never concurrently for the same object, and with rate-limited retries. Reads through `mgr.GetClient()` come from the cache; writes go to the API server.

## Testing

{{< example file="projects/shortlink-operator/internal/controller/shortlink_controller_test.go" region="setup" >}}

controller-runtime's **fake client** keeps objects in memory and understands finalizers, deletion timestamps and the status subresource, so most reconciler logic can be tested in milliseconds. The shortener is replaced by an in-memory fake that records its calls. The tests cover: create and idempotency, a URL change (recreate), a code change (delete the old link), a code taken by someone else, the API being down, and deletion.

For behavior only a real API server has (CRD validation, defaulting, webhooks), controller-runtime's **envtest** starts a local `etcd` and `kube-apiserver`, and end-to-end tests run against a kind or k3s cluster.

## Running it

```bash
cd projects/shortlink-operator
go mod tidy
go test ./...
docker build -t shortlink-operator:dev .                  # then load it into your cluster
kubectl apply -k config/default                            # CRD, RBAC, Deployment (2 replicas)
kubectl -n shortener apply -f config/samples/shortlink.yaml
kubectl -n shortener get shortlinks -w
```

During development, `go run ./cmd/manager -shortener-url=http://localhost:8080` runs the operator on your laptop against whatever cluster `kubectl` points at, with no image at all.

## Key takeaways

- A CRD adds a kind to the Kubernetes API; a controller makes the world match it; together they are an operator.
- Define the API as Go types with markers; let controller-gen generate deep-copy code, the CRD (with validation) and RBAC.
- Reconcile is level-based and must be idempotent: observe, compare, act, report. Derive external identifiers deterministically.
- Use a finalizer to clean up external resources before the object is removed.
- Report progress with status conditions; return errors to retry with backoff.
- Test reconcilers with the fake client; use envtest or a real cluster for API server behavior.
