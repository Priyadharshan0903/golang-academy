## What you will learn

- How to move data with `io.Copy` instead of reading everything into memory
- The composition helpers: `TeeReader`, `MultiWriter`, `MultiReader`, `LimitReader`
- Reading lines and words with `bufio.Scanner`, and its limits
- Why `bufio.Writer` needs `Flush`
- Connecting a writer to a reader with `io.Pipe`

## The idea

Lesson 4.5 introduced `io.Reader` and `io.Writer`. Their power comes from **composition**: small wrappers that each do one thing, stacked into a pipeline. Data flows through in chunks, so a 10 GB file uses a few kilobytes of memory.

## Copying

{{< example file="examples/m08/iostreams/iostreams_test.go" region="copy" run="go test -run Example_copy -v ./examples/m08/iostreams" >}}

`io.Copy(dst, src)` moves everything from any reader to any writer, in chunks, and returns the number of bytes copied. It is how you stream a file to an HTTP response, a response to a file, or stdin to a compressor.

`io.ReadAll` reads **everything** into one slice. That is fine for small, bounded inputs (a config file, a small API response) and dangerous for anything controlled by someone else. Wrap untrusted input in `io.LimitReader` first.

## Splitting and joining streams

{{< example file="examples/m08/iostreams/iostreams_test.go" region="tee" run="go test -run Example_teeAndMultiWriter -v ./examples/m08/iostreams" >}}

- `io.TeeReader(r, w)` returns a reader that also writes everything it reads to `w`. Here it hashes a stream while it is copied, in one pass. Any `hash.Hash` is an `io.Writer`.
- `io.MultiWriter(w1, w2, ...)` duplicates every write. Useful for writing a log to a file and stdout at once.

{{< example file="examples/m08/iostreams/iostreams_test.go" region="limit" run="go test -run Example_limitAndMulti -v ./examples/m08/iostreams" >}}

- `io.LimitReader(r, n)` stops after `n` bytes: protection against huge inputs.
- `io.MultiReader(r1, r2, ...)` reads its inputs one after the other, as one stream.

## `bufio.Scanner`: lines, words and custom tokens

{{< example file="examples/m08/iostreams/iostreams_test.go" region="scanner" run="go test -run Example_scanner -v ./examples/m08/iostreams" >}}

- `Scan()` advances to the next token and returns `false` at the end **or on error**. Always check `sc.Err()` after the loop, or read errors vanish silently.
- The default split function returns lines without the newline. `bufio.ScanWords`, `ScanRunes` and `ScanBytes` are built in, and you can write your own `SplitFunc`.
- A token is limited to **64 KiB** by default. Longer lines make `Scan` fail with `bufio.ErrTooLong`. Raise the limit with `sc.Buffer(buf, max)`, as the wordfreq project does.
- `sc.Bytes()` returns a slice that is **overwritten** by the next `Scan`. Copy it, or use `sc.Text()`, if you keep it (lesson 3.3).

## `bufio.Writer`: batching small writes

{{< example file="examples/m08/iostreams/iostreams_test.go" region="bufwriter" run="go test -run Example_bufferedWriter -v ./examples/m08/iostreams" >}}

Every `Write` on a file or socket is a system call. `bufio.Writer` collects small writes in memory and sends them in large chunks. The catch: data sits in the buffer until it fills up or you call **`Flush`**. Forgetting the final `Flush` is a classic way to lose the end of a file. `Flush` also returns any write error, so check it.

`bufio.Reader` does the same for reads, and adds helpers such as `ReadString('\n')` and `Peek`.

## `io.Pipe`: connecting a writer to a reader

{{< example file="examples/m08/iostreams/iostreams_test.go" region="pipe" run="go test -race -run Example_pipe -v ./examples/m08/iostreams" >}}

Sometimes one API wants to **write** (an encoder, a compressor) and another wants to **read** (an HTTP request body, an upload). `io.Pipe` connects them: what one goroutine writes to `pw`, another reads from `pr`. It is synchronous and unbuffered, so the writer must run in its own goroutine, and closing `pw` signals EOF to the reader. `pw.CloseWithError(err)` passes a failure through instead.

## Optional faster paths

`io.Copy` checks whether the source implements `io.WriterTo` or the destination implements `io.ReaderFrom`, and lets them do the copy directly (lesson 4.3). Files and network connections use this to copy with fewer allocations, and on Linux even without copying through user space. You get that for free by using `io.Copy` instead of a manual read loop.

## Common mistakes

### Reading everything into memory

`io.ReadAll` on an upload or a large file. Stream with `io.Copy`, or bound it with `io.LimitReader`.

### Ignoring `sc.Err()`

`for sc.Scan() {}` stops on errors as well as on EOF. Check the error after the loop.

### Forgetting `Flush`

The last chunk never reaches the file. `defer w.Flush()` is not enough on its own either, because the error is lost; flush explicitly and return its error.

### Writing your own read loop

Hand-written `for { n, err := r.Read(buf) ... }` loops often get the `n > 0` with `io.EOF` case wrong (lesson 4.5). Use `io.Copy`, `io.ReadFull` or `bufio`.

## Key takeaways

- Stream with `io.Copy`; use `io.ReadAll` only for small, bounded data.
- Compose behavior with `TeeReader`, `MultiWriter`, `MultiReader` and `LimitReader`.
- `bufio.Scanner` reads lines or words; check `Err()`, and raise the 64 KiB limit for long lines.
- `bufio.Writer` batches writes; always `Flush` and check its error.
- `io.Pipe` connects a writer-style API to a reader-style API across goroutines.
